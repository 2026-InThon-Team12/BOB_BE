# Buy or Bye (BoB) — FE 구현 명세서

> 커밋용 사본: `BoB_handoff/FE_SPEC.md` (2026-10-31). 원본 프로토타입 HTML은 별도 전달 자료이며 이 저장소에 포함하지 않습니다. 실제 API는 [최신 연동 명세](handoff-integration.md)를 따릅니다.

> 백엔드 연동 시 **11장 최신 확정 사항**과 [실제 API 계약](handoff-integration.md)을 우선합니다. 아래 FE 타입·API 경로 예시는 초기 초안입니다. HTML 화면 수정은 사용자가 진행하며 이번 반영은 백엔드·연동 명세에 한정합니다.

> 기준: 디자인 캔버스 "Buy or Bye (BoB)" 최신본 (2026-10-31)
> 함께 전달: `prototype/` 폴더 — 화면별 단독 실행 HTML. `prototype/index.html`을 열면 전체 화면을 한눈에 보고, 각 화면을 눌러 실제처럼 조작할 수 있습니다. **픽셀·색·간격·문구의 원본은 프로토타입 HTML이며, 이 문서와 충돌하면 HTML을 우선합니다.** (계산 규칙·데이터 모델은 이 문서가 기준)

## 0. 범위와 전제

- 대상: 모바일 앱 (기준 뷰포트 **390 × 844**, iPhone 14 계열). 세로 스크롤 화면은 프로토타입의 높이(최대 1200px)만큼 스크롤됩니다.
- 상태바·홈 인디케이터는 그리지 않았습니다. 실제 기기의 safe area를 사용하세요. (상단 콘텐츠 시작 ≈ 54px, 하단 탭바 높이 84px 중 하단 34px는 safe area)
- 프로토타입의 금액·물건·날짜는 **모두 예시 데이터**입니다. 상품 이미지는 회색 자리표시 또는 임시 일러스트입니다.
- 실제 기능(비전 인식, 알림, 계좌 연동, 저장, 집계)은 화면에서 "동작하는 척"만 합니다 → 9장 참고.
- 스택은 정해지지 않았습니다. React Native(Expo) / Flutter / Next.js(PWA) 어느 쪽이든 이 문서 기준으로 구현 가능합니다.

### 주요 결정 사항과 남은 선택

| 항목 | 현황 |
| --- | --- |
| 홈 화면 디자인 | 현재 홈(`Main`) + 시안 3개(`HomeA` 위계 강화, `HomeB` Buy/Bye 듀얼, `HomeC` 다크 히어로) 중 택1 |
| 할인 함정의 배송비 | OFF에서 입력한 배송비를 ON에서도 보존. 서버에 배송비를 항상 명시하며 샘플 3,000원을 자동 기본값으로 쓰지 않음 |
| 시뮬레이션 기간 중간 구간 | 3만 원 이하 3일 / **10만 원 미만 7일(가정)** / 10만 원 이상 14일 |
| 리포트의 구매 이유 라벨 | 리포트에는 축약형 "추가 할인 받으려고"로 표기 (원문: "일정 금액 이상 담으면 추가 할인을 받을 수 있어서") |
| 참은 금액 | 앱 안 가상 누적만 표시 (실제 저축 연동 여부 미정) |
| 목표 화면의 "하루 평균 저축액" | 화면의 날짜 표시를 유지. 지갑의 월 계획 저축액 ÷ 해당 월 실제 일수 사용. 설정 화면은 저축액 입력 없이 가상 적립금과 남은 금액만 표시 |

### 1.3 간격·모서리·그림자

- 화면 좌우 여백 **20px**, 카드 간격 10–12px, 카드 안쪽 여백 16–20px
- 모서리: 카드 18–24 / 버튼 12–16 / 칩 10–12 / 알약형 999
- 그림자: 기본 없음. 떠 있는 카드만 `0 8–12px 24–32px rgba(21,24,30,.08–.14)`
- 터치 영역 **최소 44px** (예외: 할인 조건 입력 한 줄은 40–42px)

### 1.4 아이콘·일러스트

- 아이콘: 24×24 viewBox, stroke 1.8, round cap/join, `currentColor` (홈·목표·리포트·지갑·알림·뒤로·닫기·체크·플러스·경고·달력·트럭·AI 반짝이)
- AI가 만든 값(카테고리 추천, 응답 요약, 인식 결과)에는 **반짝이(✦) 아이콘**을 붙여 구분
- 상품 일러스트(시안 A/B/C): 단색 플랫 SVG, 카테고리별 연한 배경색 타일. 실서비스에서는 상품 이미지로 대체

    ├─ 목표 카드 ────────────────▶ Goal
    ├─ 구매 후 점검 배너 ──────────▶ PostCheck ─▶ Report

                                                 └ Bye ▶ Goal (참은 금액 누적)

AddMethod ─┬─ 장바구니 스크린샷 ▶ ScanReview ▶ AddReason ─┬ (추가 할인 이유 있음) ▶ DiscountTrap ▶ 홈
           │                                                └ (없음) 시뮬레이션 시작 ▶ 홈

Goal ─┬─ 목표 바꾸기 ▶ GoalSetup(바꿀 때) ▶ Goal

      └─ (100% 도달) ▶ GoalDone ─ 다음 목표 정하기 ▶ GoalSetupFirst ▶ Goal

## 4. 화면별 명세

각 항목: 목적 / 구성 / 상태·인터랙션 / 데이터. 프로토타입 파일명은 `prototype/<이름>.html`.

### 4.1 홈 `Main` (시안: `HomeA`·`HomeB`·`HomeC`)
- **목적**: 오늘 할 일(저녁 질문, 결과 도착, 구매 후 점검)과 목표 진행을 한눈에.
- **구성(Main)**: 로고 `BoB / Buy or Bye` + 알림 → 오늘의 질문 카드(파랑, 품목 수, "1분 만에 답하기") → 목표 카드(진행률, 참은 금액/목표 금액, 예상 달성일) → 구매 후 점검 배너 → "시뮬레이션 중 N" 리스트(결과 도착 뱃지 또는 `n/총일` + 진행 바) → 탭바.
- **상태**: 질문 없음(오늘 답변 완료) 시 카드 → "내일 저녁 8시에 다시 물어볼게요". 시뮬레이션 0개 시 빈 상태 + 등록 CTA.
- **시안 차이**: A=큰 숫자 + 동전 저금통(목표%) + 가로 스크롤 카드 / B=Buy·Bye 저울 + 결정 카드에서 바로 Buy/Bye / C=다크 상단에 큰 숫자 + 선물상자 일러스트.

### 4.2 등록 방법 `AddMethod`
- 상단 빨간 필수 안내: **"한 번에는 같은 쇼핑몰에서 담은 상품만 올려 주세요"** (모든 방법에 적용).
- 방법 3개: 장바구니 스크린샷(추천, 파란 테두리) / **상품 URL 입력**(붙여넣기 → OG/JSON-LD 파싱, 가격 없으면 직접 입력) / 직접 입력(이름·가격).
- ‘쇼핑앱에서 공유하기’를 ‘상품 URL 입력’으로 바꾸고 URL 입력창·‘상품 정보 불러오기’ 버튼을 표시합니다. 입력 후 `POST /api/v1/product-url-drafts`로 `{"url":"https://…"}`를 전송합니다. 로딩 중 중복 탭을 막고 응답 후 이름·가격·카테고리를 확인/수정한 다음 구매 이유를 선택합니다. 초안 생성만으로 등록하지 않습니다.
- `price:null`이면 가격 직접 입력, 이미지 없으면 기본 이미지, `PRODUCT_URL_UNAVAILABLE`이면 URL을 로컬에 유지한 채 직접 입력/스크린샷 경로를 제공합니다. 전체 계약은 [상품 URL 등록 명세](handoff-integration.md)를 따릅니다. HTML 변경은 사용자가 진행합니다.
- 하단 "다른 방법": 지금 바로 쓰는 돈 → Goal, 할인 조건이 보일 때 → DiscountTrap.

### 4.3 장바구니 인식 확인 `ScanReview` (기능 3)
- 인식 품목 리스트: 체크박스(포함 여부) · 썸네일 · 이름 · 가격 · **AI 카테고리 칩** · 시뮬레이션 기간 뱃지.
- 카테고리 칩 탭 → 칩 그리드 펼침(10개). 안내 "AI는 'X'(으)로 골랐어요". 선택 즉시 접힘.
- 카테고리: 일상/생활 · 의류 · 가구/인테리어 · 가전제품 · 디지털기기 · 취미 · 게임 · 뷰티/미용 · 식품 · 기타
- 하단 CTA: "{선택 수}개 등록하고 이유 고르기" (0개면 비활성 대신 안내 토스트 권장).

### 4.4 구매 이유 선택 `AddReason` (기능 6·7)
- 품목별 단계 진행 `1 / 3`. 상단에 현재 품목 카드.
- 이유 칩(다중 선택, 순서 고정):
  1. SNS·광고를 보고
  2. 할인·한정 판매 때문에 → **선택 시 칩 바로 아래 줄에 마감일 필드** ("할인·한정 판매는 언제까지인가요?", 달력에서 선택, 표시 `M월 D일까지`, 미선택 시 회색 `O월 O일까지`)
  3. 일정 금액 이상 담으면 추가 할인을 받을 수 있어서 → **할인 함정 트리거**
  4. 스트레스·기분 전환을 위해
  5. 주변 사람이 가지고 있어서
  6. 실제로 필요해서
  7. 오래전부터 원했던 물건이라서
  8. 기타 → 선택 시 자유 입력 "어떤 이유인가요?"
- 예산 리마인드 카드(기능 7): 이번 달 자유 소비 잔액과 비교. 초과 시 주황("잔액보다 N원 비싸요"), 이내면 파랑("사면 N원 남아요"). 막대 = 잔액/가격 또는 가격/잔액.
- 안내: "{기간}일 동안 매일 저녁 8시에 물어볼게요".
- **하단 CTA 규칙**
  - 마지막 품목 전: "다음 품목"
  - 마지막 품목 & 전체 품목 중 하나라도 3번 이유 선택: 안내 "추가 할인을 받으려고 담은 물건이 있어요 ({이름들})" + 주황 **"할인 함정 확인하기"** → DiscountTrap
  - 그 외: "시뮬레이션 시작하기" → 홈

### 4.5 오늘의 질문 `DailyCheck` (기능 1) · 스와이프 상태 `SwipeYes/No/Unsure`
- 매일 20:00 알림 → 품목 카드 스택. 상단 진행 세그먼트, `현재/전체`.
- 카드: 썸네일 · 이름 · `카테고리 · 시뮬레이션 N일째 / 총일` · "이 물건을 이미 샀다고 생각해 보세요" · 품목별 질문(카테고리 템플릿 + AI 최적화) · (보정 대상이면) 주황 보정 안내.
- **답변 3종 & 제스처**: 오른쪽 = 있었어요 / 왼쪽 = 딱히 없었어요 / 위 = 잘 모르겠어요. 하단 원형 버튼(✕ 60px · ? 48px · ✓ 60px)도 동일 동작.
- 제스처 수치:
  - 판정 임계값 **90px** (세로 판정은 |dy| > |dx| 이고 dy < −90)
  - 회전 `dx / 14 deg`, 회전축 카드 하단 중앙
  - 오버레이(전면 색 + 아이콘 + 라벨) 불투명도 `clamp((거리 − 20) / 70, 0, 1)` — 있었어요 `buy`, 없었어요 `#3A404C`, 모르겠어요 `bye`
  - 뒤 카드: `scale(0.95 → 1)`, `translateY(10px → 0)` (진행도 p = 거리/90)
  - 놓았을 때 임계 미만 → 0.28s ease로 원위치 / 이상 → 화면 밖으로 0.28s 비행 후 다음 카드
  - 해당 방향 버튼 `scale(1 + 0.15 × 불투명도)`
- 완료 화면: 체크 + "오늘 질문 끝!" + 품목별 답변 요약 + 홈으로.

### 4.6 시뮬레이션 결과 `SimResult` (기능 1)
- 품목 요약(카테고리 · 가격 · 등록 이유).
- 큰 숫자 "14일 중 **3일** 필요했어요" + 14칸 그리드(있었어요 `buy` 채움 / 없었어요 `track` / 모르겠어요 점선) + 범례 개수.
- "실제로 샀다면 하루당 **53,000원**" (5장 공식).
- AI 응답 요약 카드(✦), 등록 이유 기반 패턴 경고(주황).
- 결정: **Buy**(파랑) / **Bye**(주황) 2열 + 텍스트 버튼 "조금 더 지켜볼게요 · 7일 보류".

### 4.7 구매 후 점검 `PostCheck` (기능 2)
- 구매 **14일 후** 노출. "지난 2주 동안 이 키보드를 며칠 사용했나요?" (단위는 모두 **일**)
- 선택지 2×2: 거의 매일(10일 이상) / 자주(5–9일) / 가끔(1–4일) / 한 번도 안 썼어요(0일)
- 예측 vs 실제 카드: 사기 전 예측 `14일 중 11일`(회색 막대) vs 실제 `14일 중 …`(파랑 막대) + 판정 문구. 선택 즉시 갱신.
- 하단: "디지털기기 예측 보정치에 반영했어요" → Report.

### 4.8 목표 비교 `Goal` (기능 4, 즉석 개입)
- 목표 카드: 이미지 · 이름 · 목표 금액 · 진행률(%) · 참은 금액 · 예상 달성일 · "하루 평균 N원씩 모으고 있어요".
- 진열장 진입 줄: "진열장 · 이룬 목표 N개".
- "지금 뭘 사려고 하나요?" 빠른 칩(커피 4,800 · 치킨 23,000 · 떡볶이 배달 18,000 · 인형뽑기 10,000) + 직접 입력.
- 개입 카드: "이 {물건}을/를 사면 {목표}가 **N일** 늦게 와요" + 참으면/사면 날짜 비교 + 계산식 캡션. (조사 을/를은 받침으로 결정)
- 버튼: "참을게요 · 게이지 +{금액}" → 참은 금액 누적, 토스트 / "그래도 살래요" → 기록 토스트. 100% 도달 시 토스트에 "보러 가기" → GoalDone.

### 4.8-1 목표 정하기 `GoalSetup` (바꿀 때) · `GoalSetupFirst` (처음)
- 진입: 목표 화면 "목표 바꾸기" → 바꿀 때 / 목표 달성의 "다음 목표 정하기"·진열장 "다음 목표" 빈칸·첫 목표 없음 → 처음.
- 원칙: BoB는 저금 앱이 아니므로 **저축액·저축 목표를 받지 않습니다.** 목표 게이지는 충동구매를 참아서 아낀 돈으로만 채워집니다.
- 구성: 제목("목표 바꾸기"/"목표 정하기") → "무엇을 위해 참아 볼까요?" → (바꿀 때만) 지금 목표 카드 + **"모은 N원을 새 목표로 옮기기" 스위치**(기본 켜짐) → 목표 물건 카드(사진 추가, 이름, 가격, "등록한 물건에서 고르기" 칩 — 누르면 이름·가격 자동 입력) → 미리보기.
- 미리보기: 이름·가격이 있으면 "목표까지 · 충동구매를 **N원** 더 참으면 죄책감 없이 살 수 있어요" + 시작 진행 바(옮긴 금액 ÷ 가격) + "N원을 채운 채로 시작 / 0원부터 시작". 이미 다 모였으면 "지금 죄책감 없이 살 수 있어요". 없으면 점선 안내 + 하단 버튼 회색 "이름과 가격을 입력해 주세요".
- 계산: `옮긴 금액 = 바꿀 때 && 스위치 ? min(모은 돈, 가격) : 0`, `남은 금액 = max(0, 가격 − 옮긴 금액)`.
- CTA: "이 목표로 바꾸기" / "이 목표로 시작하기" → 목표 화면.

### 4.9 목표 진열장 `GoalShelf`
- 회색 진열장(양옆 벽, 입체 선반 3단). 선반당 3칸.
- 칸 종류: 진행 중 목표(점선 + `%` + 파란 띠 "채우는 중") / 달성 목표(이미지 카드 + 하단 어두운 띠에 달성 연월 `YY.MM` + 이름 + 금액) / "다음 목표" 빈칸.
- 달성 카드 탭 → 파란 테두리 + **바텀시트**: 이름, 달성일·걸린 기간, 목표 금액 / 참은 횟수 / 가장 많이 참은 것, 산 뒤 2주 점검 `14일 중 N일 썼어요` 막대. 바깥 탭으로 닫기.
- 상단 요약: "이룬 목표 N개" + 합계 금액.

### 4.10 목표 달성 `GoalDone`
- 진입 시 **폭죽 애니메이션**: 링 팝(0.7s) + 3곳(좌·우·중앙, 지연 0 / 0.12 / 0.32s)에서 색종이 18개씩, 1.9s 동안 퍼졌다가 90px 낙하하며 사라짐. 링 탭 시 재생. `prefers-reduced-motion`이면 생략.
- "목표를 다 채웠어요 / {목표}, 이건 죄책감 없이 사도 돼요." + 통계 3칸 + "사러 가기" / "다음 목표 정하기".

### 4.11 할인 함정 확인 `DiscountTrap` (기능 5)
- **1단계 "전체 할인율을 작성해 주세요"** — 한 줄 입력: `[30,000]원 이상, [10] [% | 원] 할인`
  - 금액 칸 74px, 할인 칸 60px, 숫자만 허용, 천 단위 콤마 표시. 단위를 바꾸면 기본값(%=10, 원=3,000)
  - 그 아래 **"무료배송" 스위치**(기본 켜짐). 켜면 `[40,000]원 이상 사면 무료배송` 입력 줄 + 하단 무료배송 안내, 끄면 `배송비 [3,000]원` 입력 줄(무료배송 안내 숨김)
  - 결과 카드의 각 금액 아래에 구성 내역 표시: `상품 X원 − 할인 Y원 + 배송비 Z원` (무료면 `· 무료배송`)
- **2단계 "할인이 없어도 살 물건만 켜 주세요"** — 장바구니 품목 + 꼬리표(원래 사려던 물건 / 할인 때문에 담은 물건) + 스위치. 초기값: 구매 이유에 3번이 있는 품목은 꺼짐, 나머지는 켜짐.
- **3단계 결과**(입력·스위치 변경 즉시 재계산, 5장 공식)
  - 할인 함정(주황): "할인 받으려고 **{추가 지출}**을 더 쓰게 돼요" + 필요한 것만 사면 / 할인 받으려고 다 사면
  - 똑똑한 묶음(파랑): "어차피 살 물건이라 **{절약액}** 아꼈어요" + 할인 없이 샀다면 / 지금 결제 금액
- 무료배송 안내 줄, CTA: 함정이면 "필요한 것만 {금액}에 살게요" + "그래도 다 살게요" / 묶음이면 "이대로 살게요".

### 4.12 리포트 `Report` (기능 2·6)
- 월 이동, 요약 3칸(등록 · Bye 한 물건 · 지킨 돈), 다크 인사이트 카드("의류는 쓸 날을 4.5배 부풀려 예측했어요").
- 예측 vs 실제(카테고리별 회색/파랑 막대 2줄 + 배율 뱃지: ≥2배 주황 "N배 과대예측", 1.3~2배 중립, <1.3배 파랑 "거의 정확"). 단위 **일**.
- 구매 이유별 포기율(가로 막대, 최댓값만 주황).

### 4.13 지갑 `Budget` (기능 7)
- 이번 달 자유 소비 잔액(큰 숫자) + 사용률 막대.
- 이번 달 돈 계획 입력: 한 달 수입 / 반고정 지출(식비·야식 제외 / 생활비·월세·관리비·생활용품 / 교통비 / 저축) → "자유롭게 쓸 수 있는 돈" 자동 계산. 매달 1일 재확인.
- 등록 안 하고 쓴 돈 리스트 + "기록하기" (실제 잔고와 앱 수치 차이 보정용).

## 5. 비즈니스 규칙·계산식

| 규칙 | 식 / 값 |
| --- | --- |
| 시뮬레이션 기간 | `price ≤ 30,000 → 3일`, `price < 100,000 → 7일`, 그 외 `14일` |
| 질문 시각 | 매일 20:00, 하루 1회, 여러 품목은 카드 스택 한 번에 |
| 하루당 비용 | `price ÷ (있었어요 일수)` — 0일이면 "한 번도 필요하지 않았어요" 문구로 대체 |
| 구매 후 점검 | 구매(Buy) 결정 14일 후 1회 |
| 과대예측 배율 | `예측 사용일 ÷ 실제 사용일` (카테고리 누적). 배율 ≥ 2 카테고리는 다음 시뮬레이션에서 **보정 질문**(더 엄격한 질문 템플릿) 사용 |
| 목표 지연 일수 | `max(1, round(지출액 ÷ 일평균 저축액))` |
| 예상 달성일 | `오늘 + ceil((목표 금액 − 참은 금액) ÷ 일평균 저축액)` |
| 참기 | `참은 금액 = min(목표 금액, 참은 금액 + 지출액)` → 100% 시 달성 |
| 할인액 | `합계 ≥ 최소금액`일 때 `%`: `round(합계 × 율 / 100)`, `원`: 고정액 (합계 초과 불가) |
| 결제액 | `합계 − 할인액 + (무료배송 켜짐 && 합계 ≥ 무료배송 기준 ? 0 : 배송비)` |
| 함정 판정 | `추가 지출 = 결제액(전체) − 결제액(켜진 품목만)`. 꺼진 품목이 있고 추가 지출 > 0 → **함정**, 그 외 → **똑똑한 묶음** |
| 절약액(묶음) | `(합계 + 배송비 적용) − 결제액(전체)` |
| 무료배송 안내 | OFF는 숨김. ON의 남은 금액은 `max(0, 기준 − 합계)`. 절약액은 `기준 도달 시 결제액 − 현재 결제액`을 할인까지 다시 계산하고 양수일 때만 표시 |
| 자유 소비 | `수입 − (식비 + 생활비 + 교통비 + 저축)`, 잔액 = 자유 소비 − 이번 달 사용액 |
| 할인 함정 트리거 | 등록 묶음 중 하나라도 "일정 금액 이상 담으면…" 이유 → 마지막 품목 CTA가 할인 함정으로 |

## 8. 접근성

- 텍스트 대비 4.5:1 이상(캡션 `#646B78`까지 통과). 흰 글씨는 `buy`/`bye` 채움 위에서만.
- 아이콘 버튼은 `aria-label` 필수, 스위치 `role="switch" aria-checked`, 토글 칩 `aria-pressed`, 단위 선택 `role="radiogroup"`.

| 질문 생성 | `GET /daily-questions?date=` → 품목별 질문 문자열 + `calibrated` 여부 |
| 응답 요약 | 결과 화면용 요약 문장(AI) |
| 알림 | 20:00 일일 질문, 결과 도착, 구매 14일 후 점검 푸시 |
| 리포트 집계 | 월별 예측/실제 일수(카테고리), 이유별 포기율, 요약 수치 |
| 계좌 연동 | 현재는 수동 입력(“연동했다 치고”). 연동 시 이번 달 사용액 자동 반영 |

## 11. 최신 목표 설정·할인 화면의 백엔드 연동

사용자 확정 사항을 반영한 계약입니다. 공통 접두사는 `/api/v1`, 인증은 게스트 Bearer 토큰입니다.

| 화면·동작 | 연결 |
|---|---|
| 등록 방법 ‘상품 URL 입력’ | URL 붙여넣기 → `POST /product-url-drafts` → 상품 정보 확인/수정 → 구매 이유 → `/items/batch` (`source:URL`, `source_url` 필수) |
| 목표 설정 진입·등록 물품 칩 | `GET /goals/setup`의 `mode`, `current_goal`, `candidates` 사용 |
| 이름·금액·이동 ON/OFF 수정 | `POST /goals/preview`의 시작 적립금·남은 금액·게이지·문구 표시. 미리보기는 저장하지 않음 |
| 처음 목표 설정 | `POST /goals` |
| 진행 중 목표 바꾸기 | `POST /goals/current/replacement`, `current_goal_id`와 `carry_savings`, 새 목표 정보, 필수 `Idempotency-Key` 전달 |
| 달성 후 다음 목표 | `POST /goals/current/next`; 달성 목표의 적립금을 다시 쓰지 않음 |
| 목표 달성·진열장 | 달성 즉시 자동 진열. `GET /goals/shelf`로 조회 |
| 사러 가기 | 목표 설정에서 입력한 `source_url`을 외부로 열기. 실제 구매 확인 요청 없음 |
| 할인 화면 금액 구성 | `POST /discount-previews`의 `needed`, `all`, `without_discount` 객체에 있는 숫자 필드와 `breakdown` 표시 |
| 무료배송 안내 | `shipping_notice=null`이면 숨김. 양수인 `pay_shipping_saves`만 절약 문구에 사용 |

- 목표 변경의 ‘모은 돈 옮기기’는 기본 ON이며 `min(이전 목표 현재 적립금, 새 목표 금액)`까지만 이동합니다. OFF 또는 초과분은 이전 목표 기록에 남습니다. 예: 151,000원 적립 → 100,000원 목표로 변경하면 100,000원 이동·51,000원 보존·새 목표 즉시 달성입니다.
- 이동은 새 절약이 아닙니다. 월간 절약·지갑 금액을 늘리지 않고 원래 참기 기록의 취소도 따라갑니다. 달성 이력과 달성 당시 통계는 보존합니다.
- 목표 설정의 남은 금액은 `max(0, 목표금액 − 시작 적립금)`입니다. 월 계획 저축액을 가상 적립금에 자동 적립하지 않습니다. 목표 날짜 추정은 지갑 예산 기준이며 예산 없음·계획 저축 0이면 날짜를 계산하지 않습니다.
- **사용자가 수정할 화면**: GoalSetup/GoalSetupFirst에 상품 URL 입력 추가, GoalDone ‘사러 가기’를 그 URL에 연결, GoalShelf의 ‘산 뒤 2주 점검’ 예시 영역 제거. 진열은 구매 확인을 하지 않으므로 실제 구매일·사용일수를 표시하지 않습니다. 일반 물품 Buy 후 점검은 유지합니다.
- 사진은 현재 `image_url` 또는 기기 로컬 이미지로 연결합니다. 서버 이미지 업로드·영구 저장 기능을 새로 추가한 것은 아닙니다.
- 구매 전/후 AI 질문 원문·응답은 로컬에만 저장하며 종료 요약 때만 전송합니다. `simDays`는 마감일 단축으로 0 이상의 정수입니다. 기존 3버튼은 YES/NO/UNSURE 문항에만 적용하고, 나머지는 서버 `answer_spec`을 따릅니다.

정확한 요청·응답·오류 처리·날짜 계산은 [handoff 연동 계약](handoff-integration.md)을 참고합니다. DB는 새 API 실행 전에 마이그레이션 `0007`까지 적용해야 합니다.
