# 장바구니 인식과 평가

## 처리 구조

`LABLUP_VISION_ENABLED=true`와 `CART_LAYOUT_VISION_ENABLED=true`일 때 다음 순서로 처리한다. 먼저 OCR·픽셀 분석으로 체크 상태, 판매가 재인식, 상품 사진이 모두 확인되면 그 결과를 유지하고 상품별 사진·텍스트로 이름만 다듬는다. 이 단계에서 완전히 확인하지 못한 화면은 전체 화면과 OCR 좌표를 Lablup에 전달하여 상품별 영역을 제안받는다. AI 영역 분석은 쇼핑몰 이름이나 균등한 열 간격을 전제로 하지 않는다. AI용 화면만 축소하며, OCR·체크 상태 검증·최종 사진 자르기는 원본 해상도에서 수행한다.

1. 원본에서 OCR 텍스트와 체크박스 후보를 찾는다. 후보에는 로고도 있으므로 이 단계에서 상품 목록을 확정하지 않는다.
2. AI가 실제 상품별 체크박스 후보 ID, 선택 상태, 제목·판매가·사진 영역을 연결한다. 판매자 행, 전체 선택, 화면 밖 품목은 상품으로 만들지 않는다.
3. 서버가 영역 경계, 행 겹침, 체크박스 중복 사용 및 픽셀 상태와의 일치를 검증한다. 선택이 불확실한 품목은 자동으로 가져오지 않는다.
4. AI의 가격 위치를 같은 상품 안의 실제 OCR 줄과 연결한다. 사진 속 OCR 글자는 가격 줄에서 제외하고, AI 금액·원본 OCR·가격 영역 재인식이 일치해야 가격을 반환한다. 충돌하면 `null`이다.
5. 사진은 해당 상품 영역에 포함되고 제목·가격과 과도하게 겹치지 않는 원본 부분만 자른다. 같은 영역의 실제 사진 픽셀과 겹치면 경계를 보정한다. 생성 이미지나 다른 상품의 사진으로 대체하지 않는다.

AI 좌표 때문에 확인이 필요한 필드는 독립적인 OCR 레이아웃으로 한 번 더 확인한다. 모든 체크 상태가 명확한 OCR 레이아웃에서 제목 내용과 위치가 같은 상품으로 유일하게 연결될 때만 복구한다. 이웃 상품 제목, 중복 대응, 서로 다른 선택 상태는 복구 근거로 사용하지 않는다. 가격 재인식 기준은 그대로 적용하며, 복구된 품목에는 `OCR_LAYOUT_RECOVERED` 진단을 남긴다. AI를 재호출하지 않는다.

AI 실패·시간 초과·잘못된 출력은 OCR 기반 경로로 대체하고 응답에 대체 사실을 표시한다. 이름 생성까지 실패해도 확인된 가격·사진은 보존하고 OCR 원문 이름에 확인 표시를 붙인다. 전체 카트 모델 호출은 기본 40초, 카트 내 모델 호출은 공유 80초 예산으로 제한한다. HTTP 읽기 시간 제한은 네트워크 상태에 따라 전체 응답 시간과 차이가 있을 수 있다.

## 응답과 Android

- `items`: 선택이 확인된 상품만 포함한다. 가격이 불확실하면 해당 가격만 `null`로 남긴다.
- `review_items`: 선택 여부를 확인해야 하는 상품. Android는 별도 영역에서 **추가/제외**를 받으며, 자동으로 `items`와 합치지 않는다.
- `review_fields`: `selection`, `name`, `price`, `photo` 중 확인할 필드.
- `verification_notes`: 가격 식별 실패·OCR 불일치 등의 비민감 진단 코드.
- `source_regions`: 원본 너비/높이에 대한 0~1000 좌표. 추후 원본 대조 UI에 사용할 수 있다.
- `selection_summary`: `visible`, `selected`, `excluded`, `unknown`. 구형 OCR 경로는 `unknown`을 생략할 수 있다.
- `extraction_strategy`: `spatial_ai` 또는 `spatial_ocr`. AI 대체 경로를 AI 성공으로 집계하지 않는다.

Android는 확인 대기 목록과 초안을 하나의 SQLite 트랜잭션으로 저장한다. 선택을 확인하지 않은 초안은 등록 요청을 만들 수 없다. 구형 Android는 새 필드를 무시하므로 확인 대기 품목을 자동 등록하지 않지만, 확인 UI는 새 APK에서 제공된다.

원본·AI 응답·인식 상품 텍스트를 서버 로그나 Git에 남기지 않는다. 사진은 응답으로 앱에 전달되고 로컬 저장된다. AI 제공자의 보관 정책을 서버의 비저장 정책과 동일하다고 가정하지 않는다.

## 재현 가능한 평가

실제 원본은 Git에서 제외된 폴더에 두고 별도 JSON manifest를 만든다. 예:

```json
[
  {
    "id": "staggered-layout",
    "image": "cart.png",
    "excluded": 1,
    "expected": [
      {"price": 39500, "name_hints": ["배낭", "백팩"], "photo_box": [65,230,340,435]}
    ]
  }
]
```

`expected`는 화면 순서이며 가격은 상품 판매가, `photo_box`는 사람이 확인한 원본 상품 사진 영역이다. 틀린 사진도 가격과 이름만 맞으면 통과하던 평가를 피하기 위해 사진 영역 IoU 0.5 이상을 확인한다.

```powershell
python -m scripts.evaluate_cart --manifest tmp/cart-manifest.json --base-url https://YOUR-DEPLOYMENT --output tmp/cart-evaluation.json --runs 2
```

보호된 검증 배포는 `--vercel-cli tmp/vercel-tools/node_modules/vercel/dist/vc.js --scope YOUR-SCOPE`를 추가한다. 인증 값은 메모리/표준입력으로만 전달하고 보고서에 포함하지 않는다. 보고서는 선택·가격·이름·사진 성공 여부, 확인 대기 수, 처리 경로와 지연 시간만 기록한다. AI 응답이 달라질 수 있으므로 한 번의 성공을 안정성으로 간주하지 않는다.

운영 반영 전 기존 오류 원본, 다른 상품/배치의 별도 평가 원본, 불확실한 항목을 자동으로 담지 않는 테스트를 함께 확인한다. 합성 화면과 소수 쇼핑몰의 결과를 모든 쇼핑몰에 대한 정확도로 일반화하지 않는다.

## 2026-11-01 검증 결과와 한계

[평가 기록](cart-recognition-evaluation.json)은 원본이나 인식 텍스트 없이 지표만 보관한다.

- 에이블리·쿠팡·네이버 원본 4장 × 2회: 선택·가격·사진 연결 8/8 성공.
- 기존 OCR 경로가 처리하지 못한 비대칭 합성 화면 × 2회: 1회 성공, 1회 전체 화면 AI 시간 초과로 자동 추출 실패. 성공한 결과로 실패를 덮어쓰지 않았다.
- 상품명 단서 검사는 전체 7/10 통과했다. 이는 간결한 이름의 품질 점수가 아니다. 이름 생성 시간 초과 2회는 원문 이름과 확인된 가격·사진을 보존했고, 합성 화면 1회는 예상 이름 단서와 일치하지 않았다.
- 서버 테스트 355개 통과, 12개 건너뜀. Android 단위 테스트·APK 빌드와 확인 대기 상품의 추가/제외·로컬 저장 UI 테스트를 통과했다.

새 배치의 완전 자동 인식과 AI 명명의 안정성은 아직 개선 여지가 있다. 현재 모델의 응답 제한이 발생할 때에도 기존에 확인한 증거를 보존하고, 자동 판단할 수 없는 상품은 확인 또는 재시도를 안내한다. 이 표본으로 모든 쇼핑몰의 인식을 보장하지 않는다.
