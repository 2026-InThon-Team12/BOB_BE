# 구매 필요성 질문과 3방향 스와이프 (`swipe-v2`)

2026-11-01에 확정한 구매 전 질문 계약입니다. 아직 구매·사용하지 않은 상품이 정말 필요한지
돌아보는 질문이며, 실제 사용 경험이나 사용일수를 요구하지 않습니다.

## 고정 원본 목록

| 코드 | 변형 전 질문 | 후보 조건 |
|---|---|---|
| `SW_PRE_NEED` | 최근에 이게 없어서 불편한 적이 있나요? | 항상 |
| `SW_PRE_ALTERNATIVE` | 이미 비슷한 걸 가지고 있지는 않나요? 다른 것으로 대체할 수 있나요? | 항상 |
| `SW_PRE_TODAY` | 이걸 오늘 사용했을 것 같나요? | 자주 활용할 만한 상품만 |
| `SW_PRE_CASH` | 이 금액을 지금 현금으로 받는다면, 그래도 이걸 살까요? | 항상 |
| `SW_PRE_WEEK_AGO` | 일주일 전에도 이걸 갖고 싶었나요? | 항상 |
| `SW_PRE_WEEK_LATER` | 일주일 뒤에도 이걸 갖고 싶을까요? | 항상 |
| `SW_PRE_REPLACE` | 산 뒤에 잃어버리면 똑같은 것을 다시 살 건가요? | 항상 |
| `SW_PRE_PROMO` | 할인하지 않더라도 살 건가요? | 구매 이유에 `DISCOUNT_LIMITED` 또는 `EXTRA_DISCOUNT` |
| `SW_PRE_CUSTOM` | AI가 상품을 보고 필요성 판단에 도움이 된다고 생각한 질문 | 항상 |

대체품 질문은 **예가 구매에 긍정적**이도록 “기존 물건으로 대체하기 어려워 새로 살 필요가
있나요?”라는 한 질문으로 표현합니다. 오늘 사용 질문은 “이미 가지고 있었다면 … 활용했을 것
같나요?”라는 가정입니다. 구매하거나 사용한 것으로 단정하지 않습니다.

서버는 조건에 맞는 후보 중 최근 3개를 제외하고, 적게 나온 질문끼리 균등 무작위 선택합니다.
AI에는 선택된 코드 하나만 전달하고 원본의 의도를 유지하며 상품에 맞춰 변형하게 합니다.
추가 질문은 호환성·준비·보관·관리·적합성 등 상품 고유의 고려사항을 자유롭게 묻습니다.
`reason_other_text`도 전달하지만 일일 답변 원문은 질문 생성에 업로드하지 않습니다.
날짜별 고정 주제 순환과 마지막 날의 숫자 질문 강제는 제거했습니다.

자주 활용하는 상품 여부는 상품 유형과 기록된 구매 이유로 보수적으로 판별합니다. 요가매트,
키보드, 일상 신발, 필름, 치아 관리 제품 등의 반복 사용 가능한 유형은 후보에 포함하고,
일회용·행사·파티·기념·수집 목적은 제외합니다. 알 수 없는 일반 상품은 기본 제외합니다.

## 응답과 오류 처리

```json
{
  "template_version": "swipe-v2",
  "answer_spec": {
    "type": "CHOICE",
    "interaction": "SWIPE",
    "polarity": "PURCHASE_SUPPORT",
    "options": [
      {"code":"YES","label":"예","direction":"right"},
      {"code":"UNSURE","label":"잘 모르겠어요","direction":"up"},
      {"code":"NO","label":"아니요","direction":"left"}
    ]
  }
}
```

답변은 `{"choice_code":"YES"}` / `UNSURE` / `NO` 중 하나입니다. 모든 신규 구매 전·후
질문에서 같은 의미를 유지합니다. 숫자·주관식·장소 선택 입력은 없습니다. 모델은 선택지를
생성하지 않습니다. 상품명 뒤 목적격 조사는 `을(를)`로 정규화합니다.

모델의 잘못된 코드, 개방형 질문, 뒤집힌 긍정/부정, 구매 전 실제 사용 경험을 전제하는 질문은
한 번 보정 후 상품 유형에 맞춘 기본 문장으로 대체합니다. 이 검사는 형식과 알려진 잘못된
표현을 걸러내는 규칙이며 모든 문장의 의미를 완벽하게 판별하는 모델 평가를 대신하지 않습니다.
AI 미설정·시간 초과에도 같은 스와이프 계약을 반환합니다.

## 저장·결과·이전 기록

- `LOCAL` API 주소와 서버의 `local-v1` 저장 모드는 유지합니다. 출력의 질문 버전만 `swipe-v2`입니다.
- 기기에 저장한 당일 질문을 재사용합니다. Expo 클라이언트는 동시 요청도 하나로 합칩니다.
- 미응답인 예전 형식의 당일 카드는 새 질문으로 교체합니다. 이미 답한 예전 카드는 원문과 답변을
  그대로 보여주며 스와이프 값으로 재해석하지 않습니다.
- 종료 요약은 `reflection_counts: {YES, UNSURE, NO}`와 `purchase_support_rate`를 반환합니다.
  비율의 분모에는 모름을 포함한 신규 질문 응답 전체가 들어갑니다.
- `metric_unit=purchase_support`이며 예상 사용일수·예상 사용률·사용일당 비용은 `null`입니다.
  긍정 응답을 사용일수로 바꾸지 않습니다. 기존 숫자 질문만 있는 기록은 기존 집계대로 읽습니다.
- 구매 후 신규 질문도 3방향으로 통일하며 `LOCAL`·`ADAPTIVE`에는 별도의 4지선다 사용 빈도 설문을
  중복 노출하지 않습니다. 과거 사용량 기록과 보고서 계산은 유지합니다.

DB 마이그레이션은 필요하지 않습니다. 백엔드와 Expo 클라이언트를 함께 반영해야 화면·집계가
새 계약과 일치합니다. 실제 공급자 품질과 오류율은 별도의 운영 로그 검증이 필요합니다.
