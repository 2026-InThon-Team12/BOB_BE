# 달력 기반 목표 적립 · 2026-11-01

이번 변경은 과거의 `SavingEvent 합계 = 목표 게이지` 규칙을 대체한다.

- 잔여 자유 소비 예산 = 수입 − 필수 식비 − 생활비 − 교통비 − 계획 저축 − 기록 지출.
- 오늘을 포함한 이번 달 남은 일수로 아직 배분하지 않은 예산을 나눈다. 하루가 완료될 때 원 단위로 적립한다. 소수점 나머지는 이후 날짜에 배분한다.
- 새 목표를 만든 날 이전 날짜는 적립하지 않는다. 이번 달 여력보다 비싼 목표는 다음 달 이후로 예상한다. 미래 월 예산이 없으면 최근 입력 예산을 반복하고 `uses_previous_budget=true`로 표시한다.
- 구매는 미배분 여력을 먼저 줄인다. 부족하면 진행 중 게이지를 0까지 줄인다. `extra_spending` 모의 계산으로 구매 전후 목표 날짜 차이를 구한다.
- Bye/참기 및 그 취소는 행동 기록과 리포트에 남지만 게이지에는 돈을 만들지 않는다. 구매·지출 기록과 별개다.
- 목표 변경은 선택한 금액만 이동하며 나머지는 이전 목표에 보존한다. 같은 달 이미 배분한 예산을 새 목표에 다시 배분하지 않는다.
- 달성은 완료된 날짜 기준으로 확정하고 진열장 스냅샷을 보존한다. 구매 확인을 요구하지 않는다.

`Goal.funding`은 시작 날짜·시작 잔액·기존 지출·이번 달 선배분 금액과 종료 시 스냅샷을 저장한다. 마이그레이션 0008은 활성 미달성 목표를 전환일 0원에서 시작시키며, 과거 SavingEvent/구매/진열장 기록은 삭제하지 않는다. 기록이 있으면 downgrade를 거부한다.

API 경로는 유지한다. 목표 응답에는 `funding_method`와 `uses_previous_budget`가 추가된다. `saved_amount`는 달력 적립액이며, 리포트의 `saved_amount`는 기존에 참은 소비 합계다. 두 값을 합산하면 안 된다. `/home`, `/goals/current`, `/goals/setup`, `/goals/shelf`는 소유자 잠금 안에서 완료된 날짜를 정산한다.

소비의 근로 시간은 요청된 고정 기준 **10,700원/시간**으로 계산한다. 법정 최저임금이라는 표시는 사용하지 않는다. 즉석 소비 API의 `hourly_rate`, `work_minutes`와 질문의 서버 계산 문구를 사용한다.

현재 Expo 앱의 예산·목표·지출은 로컬 원장이다. Expo 저장소 버전 4에서도 동일한 규칙으로 전환한다. 서버와 로컬 원장을 자동 합산하거나 동기화하지 않는다. 질문·답변 원문도 기존처럼 로컬에 남는다.

장바구니 여러 장은 기존 `/cart-extractions`를 장별로 최대 2개씩 병렬 호출한다. 선택 순서를 유지하며 성공한 상품을 남기고 실패한 사진만 재시도한다. 겹친 상품은 확인 화면에서 사용자가 제외한다. 목표 사진 선택은 기존 기능을 유지한다.

배포 순서: 테스트 → DB `alembic upgrade head` → API 재배포 → `/health/ready` 및 인증된 목표/소비 API 확인. 스키마 변경은 nullable 열 추가이므로 이전 서버와 공존 가능하다.
